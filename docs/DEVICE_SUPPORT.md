# BLE device research and experimental support

Reviewed October 30, 2026. This covers every model in the [ESPHome Xiaomi BLE list](https://esphome.io/components/sensor/xiaomi_ble/). BLE advertisements, GATT readings and device control are separate capabilities: an ESPHome decoder does not establish that browser clock or settings commands exist.

Only LYWSD02 hardware is available to the maintainer. MHO-C303 has a [contributor's physical Home Assistant test](https://github.com/drslid/LYWSD02_BLE_Dashboard/pull/1#issuecomment-6524401251). **Every new profile below is experimental, implemented against published wire specifications and simulated tests; none has been physically validated by this project.** Support depends on firmware and sometimes on the exact hardware variant.

## Using the experimental profiles

In the browser, select **Device / firmware** before connecting. The default remains the existing stock clock profile. Extended profiles use the browser's full device chooser, then look up their specific services. Factory sensors provide measurements and a refresh button; clock, on-device unit and history actions are disabled where unavailable. Unsupported frames are ignored, not interpreted using a different model's layout.

PVVX must **already** be installed. Supported identity replies have protocol revision 0, firmware v4.7–v5.9, a recognized hardware ID and both display and temperature/humidity capabilities. Zigbee builds, unknown hardware/firmware and unsupported configurations are refused. The hardware IDs currently recognized are LYWSD03MMC revisions, MHO-C401/C401N, CGG1/CGG1N, CGDK2, MJWSD05MMC/English variant, MHO-C122 and LYWSD02MMC, subject to those capability checks. PIN-protected firmware is not handled by the adapter. Flashing, PIN changes and advertising-key changes are outside this implementation.

PVVX uses local wall-time seconds for command `0x23`. The implementation handles signed/fractional timezone offsets and manual correction. Command `0x55` changes only the documented flags byte and preserves the other configuration. The 12/24 h flag is enabled only for MJWSD05MMC variants and LYWSD02MMC; the same bit has another meaning on other hardware. History uses `0x35`, deduplicates indices and exports averaged samples with **raw device timestamps**, not fabricated UTC or hourly min/max. Home Assistant intentionally does not import these records as the existing stock extrema statistics. Configuring a visible clock screen remains the user's responsibility.

CGD1 needs its existing **32-hex-character pairing token**. Browser storage contains the selected profile and readings, not the token; the token field stays in the current page session. Home Assistant stores the token in its config entry so scheduled sync can reconnect. It can be replaced under **Configure** (blank keeps the existing token), followed by **Sync clock**. This is session authentication (`11 02`) only; the adapter never provisions a token (`11 01`), resets the clock or changes its alarms/ringtone. A privileged settings read must succeed before any settings/time write. Existing settings bytes are preserved except timezone, explicitly chosen units and display format. Timezone offsets must be exact multiples of six minutes; an unrepresentable offset is rejected. The time-write acknowledgement is reported as such: clock read-back, measured drift and a reliable battery percentage are unavailable.

Home Assistant discovery recognizes stock names plus `ATC_*`, `BTH_*`, `PVVX_*`, `CGD1*`, `Qingping Alarm Clock*` and `Cleargrass Alarm Clock*`. A prefix is only a discovery hint; PVVX identity is checked after connection. Other BTHome devices do not thereby become supported. Renamed PVVX devices can be selected in the browser, but currently need one of those prefixes for the custom HA integration. Factory sensor profiles are browser additions; use native HA sensor integrations instead of adding them as clocks. These changes are in the development source; installing the last tagged HACS release does not include them until a release is published.

## Verification and next devices to test

JavaScript tests exercise transport modes, frame layouts, capability checks, preservation of unrelated configuration, command failures, cancellation, history semantics and profile persistence without tokens. Home Assistant tests additionally exercise the real integration setup, credential flows, timezone handling, settings entities, connection cleanup and the existing stock clock regression suite. They simulate device replies and cannot prove radio behavior, firmware timing or the actual display.

The most useful next physical tests are **LYWSD03MMC with PVVX**, **CGDK2 with original firmware**, **Flower Care**, and **CGD1 with a known existing token**. CGD1 has the most complete factory control protocol but also the authentication requirement. CGPR1 timeout control is a reasonable later target after its full existing-pairing flow has been verified. Keep the current project name until broader support is physically established; preserve the HA domain, entity/statistics IDs and browser storage keys. See the [naming assessment](PVVX_COMPATIBILITY.md#naming-recommendation).

## Protocol sources

- [PVVX firmware source at cafd86d](https://github.com/pvvx/ATC_MiThermometer/tree/cafd86d2f091d6ac80ac9e71a3fb1862b34133be): `src/app_att.c` (write properties), `cmd_parser.h/c` (commands/identity), `app.h` (flags), `app_config.h` (model/service capabilities), `logger.h` (sample layout).
- [PVVX upstream configurator](https://github.com/pvvx/pvvx.github.io/blob/master/ATC_MiThermometer/TelinkMiFlasher.html): `setDevTime()`, record reads and CGPR1 timeout commands.
- [clOwOck protocol specification](https://github.com/MrBoombastic/clOwOck#protocol-specification) and [qingping-cgd1](https://github.com/rjocoleman/qingping-cgd1): CGD1 wire layouts and limitations. The reconnect path here follows Auth Confirm only; it does not copy the library's provisioning step.
- [WatchFlower BLE API documentation](https://github.com/emericg/WatchFlower/tree/master/docs): factory sensor wire formats. The protocol documents carry their own MIT notice; the adapters here are independent implementations.
- [LYWSD03MMC connected client](https://github.com/keks51/lywsd03mmc-client) and [Mi Temperature GATT capture](https://github.com/sidddy/flora/issues/8): factory notification layouts.
- [Native Home Assistant BTHome](https://www.home-assistant.io/integrations/bthome/): passive readings when PVVX is configured to broadcast BTHome.
